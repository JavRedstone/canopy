# OpenAI Build Week: Hackathon Summary

## Overview

**OpenAI Build Week** is a global online hackathon focused on building new applications using **OpenAI's GPT-5.6 and Codex**. The challenge encourages developers to explore what is possible with AI-powered software development, especially through agentic coding workflows.

Participants must create a working project that uses Codex with GPT-5.6 and submit it with a demo video, repository, and documentation.

**Deadline:** July 21, 2026, 8:00 PM EDT
**Format:** Online
**Prize Pool:** $100,000 USD

---

# Goal

Build a project where Codex and GPT-5.6 enable a meaningful product experience.

Projects should demonstrate:

* Strong technical implementation.
* Effective use of Codex.
* A complete product experience.
* A clear real-world impact.

---

Focus:

> AI applications that improve individual daily experiences.

* Analytics.

Tools for software developers and engineering teams.

Examples:

* DevOps automation.
* Testing.
* Security.

## 4. Education

Projects that advance AI-powered learning.

Examples:

* Student learning tools.

# Submission Requirements

A valid submission requires:

## 1. Working Project

A functional application built using Codex with GPT-5.6.

---

## 2. Project Category

Choose one track:

* Apps for Your Life.
* Work & Productivity.
* Developer Tools.
* Education.

---

## 3. Project Description

Explain:

* What you built.
* How it works.
* Why it matters.
* How Codex and GPT-5.6 were used.

---

## 4. Demo Video

Requirements:

* Under 3 minutes.
* Public YouTube video.
* Must demonstrate the project working.
* Must explain how Codex and GPT-5.6 were used.

---

## 5. Repository

Provide:

* Public repository with license, or
* Private repository shared with judges.

Include:

* README.
* Setup instructions.
* Sample data if needed.
* Clear instructions for running the project.

---

## 6. Codex Usage Evidence

Submissions should highlight:

* Where Codex accelerated development.
* Key engineering decisions.
* How Codex was integrated into the workflow.

A Codex session ID is required for the core development session.

---

# Judging Criteria

## 1. Technological Implementation

**Question:**
How deeply and effectively does the project use Codex?

Judges look for:

* Non-trivial implementation.
* Strong technical execution.
* Meaningful Codex integration.

---

## 2. Design

**Question:**
Does the project provide a complete product experience?

Judges value:

* Working demos.
* Usability.
* Coherent workflows.

A prototype that only shows a technical concept will score lower.

---

## 3. Potential Impact

**Question:**
Does the project solve a real problem?

Strong submissions:

* Have a clear user.
* Address a specific pain point.
* Demonstrate practical value.

---

## 4. Quality of Idea

**Question:**
Is the idea creative and well thought out?

Judges consider:

* Originality.
* Understanding of the problem.
* Strength of the solution.

---

# Strategic Implication

The strongest submissions will likely not be:

> "An app that calls GPT."

They will demonstrate:

> "A new workflow enabled by autonomous AI agents."

Especially for Codex, projects should showcase capabilities such as:

* Repository-level changes.
* Multi-step execution.
* Code generation.
* Testing.
* Debugging.
* Iterative improvement.

The opportunity is to build something where Codex is not just a feature, but a fundamental part of how the product works.
